Content Understanding の入出力

Azure Content Understanding は、文書・画像・音声・動画から定義した項目を抽出するサービスです。請求書、製品写真、通話、研修動画などでは、メディアごとに読み取れる情報が違います。取り出した結果を何に使うかから、フィールドを決めます。

スキーマとアナライザーで文書を分析する

スキーマはフィールド名、型、説明、必要なら配列や入れ子の構造を定めます。アナライザーは、対象とする入力、抽出の構成、スキーマを組み合わせて分析する設定です。既成のアナライザーを使う場合と、用途に合わせて定義する場合があります。

Foundry ポータルで文書のサンプルを入力し、文字や表の内容、フィールドと元の位置を確認します。たとえば「請求合計」を抽出するときは、税別小計や残高と混ざらない説明をスキーマに書きます。様式が異なるサンプルで試し、同じ項目が得られるか確認します。

Python の実装例

コードに出てくる環境変数を設定し、指定のライブラリをインストールして実行します。

# pip install azure-ai-contentunderstanding
import os
from azure.ai.contentunderstanding import ContentUnderstandingClient
from azure.core.credentials import AzureKeyCredential

client = ContentUnderstandingClient(
    endpoint=os.environ["FOUNDRY_ENDPOINT"],
    credential=AzureKeyCredential(os.environ["FOUNDRY_KEY"]),
)
operation = client.begin_analyze(
    analyzer_id="prebuilt-invoice",
    inputs=[{"url": os.environ["SAMPLE_INVOICE_URL"]}],
)
for item in operation.result().contents:
    print(item.fields)

アナライザーとスキーマを具体化する

テスト用の請求書を「明細2行、値引き1行、税額1つ」とし、請求番号を文字列、税込合計を数値、明細を品名と数量を持つ配列として定義します。汎用の文書アナライザーで文字と表を確かめた後、フィールド抽出で値引きを商品と取り違えていないかを見ます。サンプルによって予定の項目が存在しない場合は、値が欠けていることを表せるようにします。

音声・動画から構造化データを作る

通話の分析では文字起こしだけでなく、問い合わせの理由、対応、次の行動などを抽出できます。動画では発話に加え、場面、映像上のテキスト、製品の登場区間などを、目的に合わせて調べます。時刻や位置を持つ結果が必要なら、元のメディアと照合します。

クライアントでは認証した Azure Content Understanding の SDK で、対象メディアを扱えるアナライザーと入力を指定します。begin_analyze で処理を開始して完了を待ち、結果のコンテンツとフィールドを読みます。空欄、型の誤り、重要な値の矛盾を検出し、原文に戻れるようにします。

メディアで結果を変える

通話の「金曜までに見積もりを送ります」なら、誰が何をいつまでにするかをフィールドにします。商品紹介動画なら、映像中の型番、発話で説明した機能、登場する区間を別々に記録できます。音声と動画で使うアナライザーを選び、処理完了後にタイムスタンプやフィールドを元メディアと照合します。

演習

Content Understanding のプレイグラウンドから文書や録音を分析し、クライアントで結果を扱います。

  1. 請求書等をサンプルとして選び、既成のアナライザーで出力される文字・表・フィールドを見ます。
  2. 日付や金額を追加するなど、目的に合わせたフィールドを定義します。2種類のレイアウトで同じ値が取れるか確認します。
  3. 録音または動画を対象に適したアナライザーで処理し、発話・要約・時点など何が返るかを確認します。
  4. アプリから分析を開始し、完了を待って結果を受け取ります。値が欠損したレコードが自動登録されない条件を入れ、サンプルで試します。
