分析結果の使い道を決める

問い合わせにラベルを付ける、個人情報を隠す、レビューで不満の対象を抽出するなど、目的を定めます。自由な指示で柔軟に分析する汎用モデルと、専用機能を決まった形式で提供する Azure Language を比較します。

汎用モデルと Azure Language でテキストを分析する

汎用モデルには、キーフレーズ、固有表現、感情とその対象を指定の形式で返すよう依頼できます。たとえば「配達は速かったが冷凍品が解けていた」では、配送速度と温度管理を別の評価対象にします。利用条件に合う場合は構造化出力を指定し、受け取った型を検証します。

Azure Language には言語検出、固有表現認識、感情分析、キーフレーズ抽出、個人を特定できる情報（PII）の検出などがあります。言語検出で入力に合う処理を選び、PII 検出のマスク済み結果はログ共有などに使えます。検出漏れの可能性は代表例で確認します。

目的別に返ってくる値を比べる

「大阪支店へ電話したら案内は丁寧だったが、待ち時間は長かった」というレビューでは、キーフレーズは支店・案内・待ち時間など、固有表現は場所などを返します。対象別の感情分析を使うと、案内は好意的、待ち時間は否定的という結果を同じ文から得られます。

アプリで集計するなら文書 ID と対象、評価を保存します。言語検出の信頼度が低い短文や、人名や電話番号が残っているマスク済みテキストは、確認対象にできます。

Python のクライアントを作る

汎用モデルの場合は OpenAI Python ライブラリでクライアントを作り、Responses API に対象テキストと出力条件を渡します。エンドポイント、認証設定、デプロイ名は環境で設定し、秘密鍵をリポジトリに置かないようにします。

Azure Language では azure-ai-textanalytics の TextAnalyticsClient を構成し、たとえば detect_language や recognize_pii_entities に文字列のリストを渡します。文書ごとの結果やエラーを調べ、検出ラベル、信頼度、マスク済みテキストなど必要な値を読みます。複数件を処理するなら文書 ID を結果と一緒に扱います。

Python の実装例

コードに出てくる環境変数を設定し、指定のライブラリをインストールして実行します。

# pip install azure-ai-textanalytics
import os
from azure.ai.textanalytics import TextAnalyticsClient
from azure.core.credentials import AzureKeyCredential

client = TextAnalyticsClient(
    endpoint=os.environ["AZURE_LANGUAGE_ENDPOINT"],
    credential=AzureKeyCredential(os.environ["AZURE_LANGUAGE_KEY"]),
)
documents = ["梱包はきれいでしたが、配達が遅かったです。"]
for result in client.analyze_sentiment(documents, show_opinion_mining=True):
    if result.is_error:
        print(result.error.code)
        continue
    print("文書全体:", result.sentiment)
    for sentence in result.sentences:
        for opinion in sentence.mined_opinions:
            print(opinion.target.text, opinion.target.sentiment)

テキスト分析の出力を検証する

汎用モデルに「topic と sentiment の二つのフィールドを持つ配列」と指示したら、アプリ側で JSON として解釈し、評価値が許容リストに含まれるか確認します。Azure Language の専用クライアントでは、正常に分析できた各文書から対象語とその評価を取得します。複数件のうち1件だけ入力が無効なら、他の結果は残し、その1件を記録して再処理できます。

MCP を使ってエージェントに分析ツールを追加する

Model Context Protocol（MCP）は、エージェントが外部ツールの定義を知り、決められた入力で呼び出すための仕組みです。Azure Language の MCP サーバーをツールとして接続できる構成では、利用する分析機能と認証、アクセス範囲を設定します。

ポータルでエージェントにテキスト分析を依頼し、適切なツールが選ばれたか、結果を正しく説明したかを確認します。入力不足やツールが利用できないときの応答も試します。

エージェントの実行履歴を確認する

MCP に接続したエージェントへ「この文に住所が含まれるか調べて」と依頼し、どのツールを呼び、どの入力を渡し、何が返ったかを確認します。ツールが使えない場合にモデルが「検査済み」と回答してしまわないよう、失敗時は分析できなかったと伝える指示を入れて試します。

演習

Foundry で文章を分析し、同じ目的を汎用モデル、Azure Language、エージェントで試します。

  1. チャットでレビューの評価対象、評価、根拠を JSON 形式で返すように指示し、複数の意見がある文を試します。
  2. Python で汎用モデルを呼び、出力が期待する構造かを確かめます。続けて Azure Language で同じ文を分析し、言語検出や感情など返ってくる専用項目と比べます。
  3. 実習で案内されている Azure Language の機能をエージェントにつなぎます。テキストが空のとき、明確な感情語がないとき、複数の言語が混ざるときを試します。
